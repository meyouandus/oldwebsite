language.md
House rules for written output. Applies to everything - documents, specs, proposals, emails, notes, UI copy. Carry this file into any project and follow it by default.

The core idea
Let the words explain the concept. Don't decorate them. If a sentence works without an adjective, remove the adjective. If an idea is clear in ten words, don't take twenty.
Plain is not the same as flat. Short sentences, concrete nouns and specific detail carry more weight than emphasis does. "Blue Civic near the junction" beats "a suspicious vehicle was observed nearby."

Punctuation
Never use em dashes. Use a hyphen with spaces either side ( - ), or rewrite the sentence so it doesn't need one. Rewriting is usually better.
Avoid the colon-then-list construction. It reads as machine-generated. Either write the list as prose, or use a heading and let the items stand on their own.

Banned and suspect constructions
"Not only... but also" - never. Split it into two sentences.
Sentences starting with "This" - a real tell. "This means the build is simpler" becomes "The build gets simpler" or "That means the build is simpler." Watch for it at the start of paragraphs especially.
The word "crucial" - almost nobody writes it. Use "matters", "the point is", or cut the qualifier and state the thing.
Three-part lists with matching rhythm - "faster, cheaper, and easier to build" reads like a slogan. Break the pattern, drop one item, or vary the length of each part.
Hyperbole and stacked adjectives - "genuinely transformative", "incredibly powerful", "seamlessly integrated". Say what it does instead.
Other words worth suspecting because they cluster in machine writing. Delve, leverage, robust, holistic, landscape, journey, unlock, elevate, harness, tapestry, testament. None are banned outright but each one deserves a second look.

Structure
Front-load the point. Say what the thing is before explaining why it matters.
Keep outputs scannable. Headings that describe content rather than tease it. Short paragraphs. White space.
Vary sentence length deliberately. A run of medium-length sentences with the same shape flattens everything. One short sentence after two long ones does a lot of work.
Bold sparingly, for the claim in a paragraph rather than for keywords scattered through it.

Tone
Colloquial but precise. Write the way an experienced person explains something to a colleague they respect. No lecturing, no salesmanship, no performance of enthusiasm.
Direct about problems. If something doesn't work, say it doesn't work and say why. Hedging reads as either evasive or unclear.
No filler openers. "It's worth noting", "in today's landscape", "at its core" can all be deleted with nothing lost.
Confidence without inflation. State findings and let the reader judge. Avoid summing up with a grand closing sentence that restates what was already said.

Quick check before sending
Read it back and look for the tells. Any em dashes. Any paragraph starting with "This". Any colon followed by bullets. Any three-item list with identical rhythm. Any adjective doing no work.
Then ask whether a person who knows the subject would write it this way. If it sounds like it was produced rather than written, rewrite the parts that sound produced.
